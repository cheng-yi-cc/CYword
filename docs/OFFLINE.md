# 离线词书、自动同步与恢复

本文描述 Windows 0.4.13 / Android 0.1.11 的离线、自动同步和恢复行为。真实设备结果及测试覆盖限制见 [验收记录](FIRST-RELEASE-ACCEPTANCE.md)。

## 使用规则

完整六级词书、5166 条发音、原配图和音标字体预装在 Windows 和 Android 安装包中。首次联网登录后直接读取包内资源，不复制整本词书到 IndexedDB，也不随进度同步重新下载词书。官网不包含完整词书或用户进度。

评级先可靠保存本机进度及待同步标记，再确认并进入下一词。联网时自动同步；断网、超时和服务错误不回滚已保存记录。已有有效本机记录可立即离线学习；新设备须先成功读取云端状态，网络失败、无效响应和损坏本机都不能当作空账号上传。

当前计划位置是顺序第一个未完成日，与自然日期、时区无关。三档有效评级都算学习覆盖；复习日要求全部前置学习和复习完成，复习记录必须属于本轮。合法跳过后无待复习词须明确确认；搜索评级不会伪造复习记录。全部完成后显示结束状态。

## 自动同步

Windows 和 Android 共用 ProgressSync。应用启动、网络恢复、重新登录、回前台和评级后触发同步；双方在前台时每 5 秒检查。约 15 秒发现对端更新是初始验收目标，实际延迟需以真实双端记录为准。

每个词使用逻辑版本 `(counter, actor)`：修改时在已观察计数上加一，离线同时修改且计数相同时按 actor 字典序收敛。它不声称还原无法观测的真实先后，也不以已掌握优先，允许降低熟练度。时间戳只记录事件；既有无版本的维护者快照保留兼容读取，但新评级都使用逻辑版本。

不同词的修改合并保留，正式复习记录按轮次与单词去重。队列、已复习集合和完成状态按有效记录重算。会话固定启动日期与轮次，远端刷新不把当前词的评级写入下一日。

本机写入、远端合并和上传确认串行执行；收到较早上传的成功响应，不能把之后新增的本机评级一并标记为已同步。待同步标记跨重启保留。服务端用修订号防止并发覆盖，409 合并后最多连续尝试 5 次；持续失败指数退避，最长 60 秒。未改变的修订号返回空增量，传输层向同步引擎返回逻辑 304，避免重复解析和写盘。

账号菜单显示正在同步、已同步、已保存本机等待同步、离线、登录过期或错误。401 或令牌到期暂停远端请求，保留受保护会话和本机学习；点击“未登录”重新验证，同账号登录后自动补同步。账号切换后旧响应不写入新账号。没有仅本机开关或一次性旧云端导入流程，也没有用户手动导入、导出按钮。

## 本机耐久性与退出

- Windows：`userData/accounts/<账号哈希>/progress.json`，临时文件写入并同步后原子替换，保留上一份有效副本。会话由系统加密写入 `session.json`。
- Android：按账号写 Preferences，原生同步 `commit()` 一次提交主记录和副本；失败恢复内存并向界面报告。会话使用 Keystore AES-GCM，不降级为明文。
- 浏览器预览：localStorage，复用主记录、副本与异常保留逻辑。不是正式桌面端存储。

进度采用可逆词 ID 字典加 gzip；不会删减学习记录或复习历史。损坏原件先保留，再尝试有效本地副本或云端；没有可恢复记录时明确提示，不静默重置。会话损坏也应进入可恢复登录界面。

关闭、退出、切换账号和安装更新都先检查本机保存。本机失败阻止离开并允许重试；本机成功但云端未完成时可明确确认后退出，待同步记录仍在。Android 不依赖进后台前上传完成；系统终止后重启继续补同步。

## 云端快照与保障边界

D1 当前记录按账号和词书独立存储；首发候选改用 `POST /api/progress-incremental`、协议 2。每词保存一个有界记录，另存日期记录。单次评级只上传变化的记录；每批最多 24 条、请求最多 96000 字节。分批暂存期间对其他设备不可见，最后按修订号原子提交，D1 同一事务校验前置学习/复习计数并更新可见记录。响应丢失后重读确认，不重复增加历史。读取每页最多 32 条，客户端收齐稳定修订号并完成业务校验后才落盘，分页中途失败不发布半份进度。未改变时仅读取修订号，跳过全书解析与本机重写。

选择增量方案的原因是隔离 Cloudflare 免费环境实测旧全量快照接口出现 CPU 超限；维护者选择保留免费档。旧 `/api/progress`、`learning_progress` 和历史快照保留作为历史数据与恢复证据，新客户端不自动退回全量上传。不能只把已发布旧客户端指向空的 v2 存储；首发部署先应用迁移、部署新函数，再发布两端候选。

每账号最多保留三个未提交批次；新批次可淘汰最旧的未提交批次，失败设备保留本机记录后重试，已提交记录不变。进程内保存远端增量缓存；进程重启后首次重新分页读取云端，高进度和高延迟网络下可能持续数分钟，期间仍可使用已有本机记录。它与双方持续前台时的小增量接续延迟不同。

`progress_checkpoints_v2` 每账号/词书/小时槽保留首个有效快照，最多过去 7 天内的 24 个槽，按词 ID 前缀拆成有界块，由 D1 生成，Worker 不解析全书。单账号恢复先验证快照，按当前修订号比较并交换，完整保存被替换的原始记录到 `progress_recovery_archive_v2`，重建统计并提高词汇及复习评级逻辑版本；不使用整库回滚恢复一个账号。内部恢复命令与演练结果见运行手册及验收记录。历史 v1 快照仍在原表。

已成功同步的记录可以换设备恢复。彻底离线、尚未上传且随后设备被清空的记录没有云端保障。恢复会提高快照中词条的逻辑版本，但未知离线设备上的后续操作重新上线时仍可能合入；执行恢复前应暂停相关设备同步并核对范围，不能承诺完全抹除尚未见过的事件。

## 资源与开发预览

`npm run build` 先执行规范数据校验，逐词构建完整资源清单。缓存音频和图片复用前校验哈希；缺失资源阻断构建。图片仅在逐图 RGBA 像素一致且文件更小时使用无损 WebP；原巧记、例句、引用、录音字节和图像内容不修改。音标字体为随包 Gentium 7.000。Windows 将 `dist/book/**/*` 独立放入 `app.asar.unpacked`，UI 更新不牵动整本 ASAR。

`npm run dev:web` / `npm run dev:mobile` 使用 5173；`npm run dev` 打开 Electron；官网 `npm run dev:site` 使用 5174。默认开发账号和同步接口是隔离模拟，词书直接读 `data/`，媒体按需复用 `CYWORD_PREVIEW_BOOK`、`dist/book`、构建缓存或本机完整 APK。缺失媒体明确报错，不暗中全量下载。

`CYWORD_REAL_AUTH=1` 会把开发认证和**双向进度读写**转向实际服务，可能更新所登录账号；不要用日常账号做故障注入。隔离安装包通过 `CYWORD_ACCEPTANCE_ORIGIN` 在构建时指定独立 HTTPS 后端，使用专用桌面数据目录和安卓包名；默认正式构建保持官网源。旧下载资源路径仅作回归时设置 `VITE_CYWORD_BOOK_DOWNLOAD=1`，它不关闭同步。

全量检查命令：`node scripts/audit-bundled-book.mjs` 核验实际构建词条与全部媒体；`node scripts/audit-book-render.mjs` 渲染全部词条和内容标签；`npm run test:bundled:ui` 检查正常/减少动画的随包流程。安装器、真机和真实双端结果须单独记录。
